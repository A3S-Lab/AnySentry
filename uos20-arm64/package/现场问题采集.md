# 现场问题采集

把出现问题时的主机状态、服务日志、安装记录和模型配置状态打成一个文件，再原样拷回。脚本只读取状态，不改配置、不重启服务、不访问外网。密钥、令牌和口令只保留“是否已设置、长度、指纹”，不保留原文。

## 1. 适用时机

- `./install.sh` 中途失败，或升级后自动回到上一版；
- 页面打不开，或模型连通性测试失败；
- Collector 不健康、探针数量不对、事件不再增长；
- 某个服务占用过高，已经按下面的命令临时停止，仍需要保留停止前的记录。

未知工作负载默认只保留发现级样本，明文和大体积事件会被丢弃。这是发布配置，不是采集故障。模型连接保存在 API 进程内存里，API 重启后需要在策略配置页重新测试并应用。

## 2. 生成回传文件

已安装时：

```bash
sudo /opt/anysentry/collect-support-bundle.sh
```

安装尚未完成、只解压了发布包时，进入解压目录：

```bash
sudo ./collect-support-bundle.sh
```

指定输出路径：

```bash
sudo /opt/anysentry/collect-support-bundle.sh /mnt/anysentry-support.tar.gz
```

默认文件：

```text
/tmp/anysentry-support-<主机名>-<时间>.tar.gz
```

通过文件传输把这一个 `.tar.gz` 拷回。不要打开后删减，也不要另存成截图。

## 3. 压缩包内容

| 文件 | 内容 |
| --- | --- |
| `summary.txt` | 架构、内核、服务是否 active、安装阶段、模型项是否已设置 |
| `host.txt` | 操作系统、glibc、页大小、CPU、内存、磁盘、cgroup、BPF sysctl |
| `services.txt` | 各单元状态、重启次数、当前内存 |
| `performance.txt` | 负载、内存、磁盘，以及相关进程的 CPU 和 RSS |
| `model-config.txt` | 环境中的模型地址、模型名、超时；密钥只留指纹 |
| `model-connections.json` | 本机 API 的模型连接响应，密钥字段已替换 |
| `health.txt` | 健康接口、Collector 状态、`attachedProbes` |
| `install/` | 最近一次安装的 `summary.txt`、`current-stage.txt`、日志尾部、回滚日志 |
| `journal/` | 各服务最近日志，单文件截断 |

## 4. 安装和升级失败

预检不改服务：

```bash
./install.sh --check
```

正式安装或升级：

```bash
./install.sh
```

失败后先看本版诊断目录：

```bash
cat /var/log/anysentry/install/0.4.0-compat9/summary.txt
cat /var/log/anysentry/install/0.4.0-compat9/current-stage.txt
less /var/log/anysentry/install/0.4.0-compat9/install.log
```

快速入口 `/tmp/anysentry-install-0.4.0-compat9` 指向同一目录。

`rollback=completed` 表示验证失败后已经恢复上一版程序和 `/etc/anysentry/anysentry.env`。上一版程序在 `/opt/.anysentry.rollback.*`，失败现场在 `/opt/anysentry.failed.*`。自动回滚还在进行时，不要手工移动 `/opt/anysentry`。

`rollback=failed` 时，按 [DEPLOYMENT.md](./DEPLOYMENT.md) 的“手工恢复上一程序”处理，然后再执行采集脚本。

## 5. 临时停止占用过高的服务

数据目录 `/var/lib/anysentry` 保留。按需要停止，不必一次全停。

| 目的 | 命令 |
| --- | --- |
| 停止采集（通常是 CPU 最高的部分） | `systemctl stop anysentry-observer.service` |
| 停止 Flink | `systemctl stop anysentry-flink-job.service anysentry-flink-taskmanager.service anysentry-flink-jobmanager.service` |
| 停止流处理和复合研判 | `systemctl stop anysentry-stream-worker.service anysentry-composite-judge.service` |
| 停止快速研判和深度研判 | `systemctl stop anysentry-fast-judge.service anysentry-l3-worker.service` |
| 只保留页面和数据库 | 再执行 `systemctl stop anysentry.service` 之外的上述命令；页面本身对应 `anysentry.service` |

恢复时按依赖顺序启动：

```bash
systemctl start anysentry-clickhouse.service anysentry-redis.service anysentry-kafka.service
systemctl start anysentry-flink-jobmanager.service anysentry-flink-taskmanager.service anysentry-flink-job.service
systemctl start anysentry.service
systemctl start anysentry-fast-judge.service anysentry-l3-worker.service
systemctl start anysentry-stream-worker.service anysentry-composite-judge.service anysentry-supply-chain.service
systemctl start anysentry-observer.service
```

本发布包默认启用 fast-judge、composite-judge、stream-worker 和 Flink。`ANYSENTRY_STREAMING=on`，API 会向本机 Kafka 发送事件。

## 6. 模型与令牌

首次安装后，`/etc/anysentry/anysentry.env` 中的模型地址和密钥为空，L3 默认关闭。填入 OpenAI 兼容地址后再打开 L3：

```ini
ANYSENTRY_LLM_BASE_URL=https://<LLM服务地址>/v1
ANYSENTRY_LLM_MODEL=<模型名>
ANYSENTRY_LLM_API_KEY=<API密钥>
ANYSENTRY_ASYNC_JUDGE=on
ANYSENTRY_L3_ENABLED=true
ANYSENTRY_L3_MODE=completion
ANYSENTRY_L3_TIMEOUT_MS=300000
ANYSENTRY_L3_RETRY_TIMEOUT_MS=330000
A3S_SENTRY_L3_URL=https://<LLM服务地址>/v1
A3S_SENTRY_L3_MODEL=<模型名>
A3S_SENTRY_L3_KEY=<API密钥>
```

保存后：

```bash
chown root:root /etc/anysentry/anysentry.env
chmod 0600 /etc/anysentry/anysentry.env
systemctl restart anysentry.service anysentry-fast-judge.service anysentry-l3-worker.service
```

页面上的策略配置是运行中的内存状态。API 重启后要在策略配置页重新测试并应用，否则环境文件里的种子值和页面显示会不一致。采集脚本会同时记录环境文件（已脱敏）和本机模型连接接口，用来区分“没写入环境文件”和“页面应用丢失”。
